## Decisions
- Tech stack: Vite + React + TypeScript; React Router for SPA navigation; React Context + `useReducer` for the central store; localStorage persistence; Vitest as a dev dependency for domain unit tests.
- Deploy target: Vercel static deployment with `vercel.json` SPA rewrite. User will create/connect the GitHub repository and configure Vercel.
- Git workflow: work directly on `main`; do not create a branch, commit, or push unless the user asks.
- Role home pages: Picker → Orders & Picking; Receiver → Receiving; Manager/Admin → Dashboard. Hide Dashboard from Picker/Receiver. Unauthorized route access redirects to that role's home page.
- Product reorder points remain per-product; Manager/Admin can edit them in Product Detail. Settings default reorder point starts at 10 and applies only to future products; this prototype does not add products, and Reset demo data preserves the setting.
- Users & Roles omits Active status because REQUIREMENTS.md 6.10 does not define it and `User` has no status field. Account activation/deactivation and status remain roadmap work tied to organization SSO.
- Role capability display is derived from `domain/access.ts`; action guards use the same capability function. Reset confirmation is shared between Settings and the profile menu.
- Persistence v5 fills missing Settings while preserving saved Products, Locations, Orders, Movements, Users, session, and theme. `lastSavedAt` is envelope metadata outside StoreState and does not trigger another persistence write.
- Replenishment suggestion: `max(0, reorderPoint + averageDailyUse × leadTimeDays − onHand)`, rounded up to an integer; show the formula and values in the explanation.
- Location seed uses 56 locations across four zones (40 occupied by unique SKU assignments and 16 vacant); all include capacity and dispatch coordinates/distance. High-activity SKUs are close to dispatch on Levels 1–2; products in a category stay within one zone or two adjacent zones.
- Reset demo data resets products, locations, orders, and movements to seed values while preserving session and theme. A zero-difference stock count creates no Movement and shows a “stock matches” message; count-event logging is Roadmap.
- Round 1 sequence: Step 1 app scaffold and Vercel rewrite; Step 2 domain/store/seed/persistence and Vitest tests; Step 3 Login/Role/layout/theme; Step 4 deployment verification. Stop after each requested review point; currently authorized through Step 3 only.
- Demo login accepts any or blank credentials; a blank username becomes `Demo <Role>`. Session (user + role) and theme persist through the versioned store. Role menus, home routes and access checks live in pure functions in `src/domain/access.ts`.
- Each seed product now declares explicit category and unit values. Loading existing persisted products refreshes only category/unit from the seed while preserving quantities, reorder points and movements. Stock alerts are ordered Out → Critical → Low, then by SKU.
- Vitest pinned to 4.1.12 for Node compatibility and to use the patched release; latest `npm audit` reported zero vulnerabilities.
- All numeric text fields must use the shared `parseWholeNumber(raw)` parser so accepted values are ASCII digits and safe integers.
- Round 4a Dashboard definitions: “today” uses the `Asia/Bangkok` calendar date derived from each selector's injected `now`; “due soon” means an open order due from now through the next 24 hours, while overdue means due before now. Dashboard urgent orders sort overdue first, then due time ascending, and show at most five. Items needing attention is Low + Critical + Out per REQUIREMENTS.md section 8. Seed `dueAt` values are ISO timestamps with times; no seed change was needed.
- Round 4a Dashboard typography: compact secondary text uses the existing 11px scale, badges use the existing 10px scale, and headings/KPI hierarchy follows shared page typography. On a 375px responsive viewport the date/quantity labels remain separated in the horizontally scrollable 14-day chart; KPI text wraps cleanly without clipping.
- Round 4b Stockout Prediction seed examples: SKU-007 PICK 30 / lead 9 days (At risk); SKU-008 PICK 32 / lead 10 (At risk); SKU-009 PICK 48 / lead 11 (High); SKU-016 PICK 82 / lead 14 (At risk); SKU-023 PICK 60 / lead 14 (Watch). On-hand and the stock-status distribution remain unchanged; Movement chains, ending on-hand, and Order picked quantities match.
- Round 4b localStorage: `STORE_VERSION` was 3 because it versions the persisted schema, not seed contents. Existing localStorage business data is preserved and does not adopt the new prediction examples automatically; use the confirmed **Reset demo data** action to load the new seed.
- Round 4c Short pick definition: count a completed Order whose `completedAt` falls within the trailing 7 days (inclusive at exactly 7 days and up to `now`) and has at least one line with `shortQty > 0`; one issue per Order, merged with other Order rules using the highest severity. The displayed reason names the Order completion and short-line count, not a short event date.
- Round 4c Short pick limitation: use `completedAt` as a proxy because the store does not record the timestamp of each short line; more precise timing requires adding a short-line timestamp in a future round.
- Round 4d Picking Route uses `(0,5)` as the dispatch coordinate because it matches `dispatchDistanceMeters` for 3/40 locations, compared with 2/40 for `(16,5)`. Route calculations and the SVG use Manhattan distance from the explicit point and Location `coordinates` only; they do not use `dispatchDistanceMeters`.
- Round 4d Order detail route switch was skipped because `pathLines` determines both visible order and the `Next line` target; changing it would change picking behavior, while changing display alone would make the order and Next line inconsistent.
- Round 4e fast-moving definition: calculate the nearest-rank 75th percentile using only SKUs with positive PICK demand in the trailing 30 days; every SKU tied at or above the cutoff is fast-moving, and SKUs with no recent demand are slow-moving. Seed cutoff at implementation time: 11 PICK units per 30 days.
- Round 4e Receiving banner was skipped as requested; Receiving was left unchanged to keep this step scoped to AI Insights.
- Round 4e localStorage migration v4 adds missing seeded Locations by ID only; saved Location values and all saved products, orders, movements, session and theme remain unchanged. Reset demo data restores the 56 seeded Locations while preserving session and theme.
- Round 4e AI Insights section shortcuts stay sticky below the Topbar; section scroll margins account for both bars, and the shortcut row scrolls horizontally within its own bounds on narrow screens.
